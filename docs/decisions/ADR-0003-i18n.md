# ADR-0003 — Internationalization Strategy (CZ + EN)

- **Status**: accepted
- **Date**: 2026-05-17
- **Tags**: stack, process
- **Deciders**: architect

## Kontext

Investio targetuje primárně český trh (CZ default), ale chce být přístupný i anglicky mluvícím (EN secondary). i18n od dne 1 = nutnost, retrofit by byl drahý. Klíčové výzvy:

1. **Sdílené message bundles mezi web a mobile** — bez sharingu hrozí drift (klíč existuje na webu, chybí na mobilu, user vidí raw key).
2. **Různé i18n knihovny per platform** — Next.js má skvělý `next-intl` (RSC support, middleware routing), React Native nemá rovnocenný ekvivalent, standardem je `i18next` + `react-i18next` + `expo-localization`.
3. **Formátování čísel a měn per locale** — `1 234,56 Kč` (cs-CZ) vs `1,234.56 CZK` (en-CZ). Klíčové pro finanční app.
4. **Plurals + variables** — "Za 1 rok" vs "Za 5 let" vs "In 1 year" vs "In 5 years". Slovanské jazyky mají 3 plural forms (one/few/many), angličtina 2 (one/other).

## Rozhodnutí

**Web**: `next-intl` v3+. **Mobile**: `i18next` + `react-i18next` + `expo-localization`. **Sdílené message bundles**: `packages/i18n/locales/{cs,en}.json` — single source of truth, oba clients čtou stejné JSON.

**Formát message bundlu**: **ICU MessageFormat** (`next-intl` to nativně podporuje, `i18next-icu` plugin pro mobile). Důvod: ICU řeší plurals + selectors + nested formatting standardním way → konzistence napříč platformami a kompatibilita s pro budoucí překladatelské tooly (Crowdin, Lokalise umí ICU).

**Formátování čísel a měn**: jeden helper v `packages/shared/src/formatters/currency.ts` postavený na `Intl.NumberFormat` — nativně podporovaný v Node (web SSR), browser, i v Hermes engine od RN 0.73+. Žádné `numeral.js` / `accounting.js` dependency.

### Message bundle struktura

```
packages/i18n/
├── locales/
│   ├── cs.json          # source of truth (CZ je primární trh)
│   └── en.json          # paralelní struktura
├── src/
│   ├── index.ts         # exporty: getMessages(locale), defaultLocale, locales[]
│   └── keys.ts          # type-safe key paths (generated z cs.json)
├── scripts/
│   └── check-parity.ts  # CI script: ověří že en.json má všechny klíče z cs.json
└── package.json
```

### Web (Next.js + next-intl)

- **Routing**: `app/[locale]/...` segment-based. Locales: `cs` (default), `en`.
- **Middleware**: `middleware.ts` detekuje locale (1. URL segment, 2. `NEXT_LOCALE` cookie, 3. `Accept-Language` header, 4. fallback `cs`).
- **Server Components**: `getTranslations({locale, namespace})`.
- **Client Components**: `useTranslations(namespace)`.
- **Currency formatting** v RSC i client: `useFormatter()` z next-intl + `Intl.NumberFormat` fallback v `packages/shared`.
- Messages načítané dynamic import z `@investio/i18n/locales/${locale}.json` v `i18n.ts` config.

### Mobile (Expo + i18next)

- `i18next` instance v `apps/mobile/lib/i18n.ts`.
- **Locale detekce**: `expo-localization` `getLocales()[0].languageCode` (jednorázově při startu) — uloženo do `expo-secure-store` aby user override při language switch v in-app settings persistoval.
- **Resources**: import přímo z `@investio/i18n/locales/cs.json` + `en.json` (Metro to resolvuje přes workspace).
- **Plurals**: `i18next-icu` plugin (parita s next-intl ICU formátem).
- **`<Trans>` komponenta** pro inline rich text + interpolace.
- Currency formatting přes stejný `packages/shared/src/formatters` helper.

### `formatCurrency` helper (sdílený, signatura)

```ts
// packages/shared/src/formatters/currency.ts
export function formatCurrency(
  value: number,
  currency: "CZK" | "EUR" | "USD",
  locale: "cs" | "en"
): string;
// Použije Intl.NumberFormat s style: "currency"
// cs-CZ + CZK → "12 345,67 Kč"
// en-US + USD → "$12,345.67"
// en-US + CZK → "CZK 12,345.67" (currency code fallback)

export function formatPercent(
  value: number,        // 0.05 = 5 %
  locale: "cs" | "en",
  fractionDigits?: number
): string;

export function formatCompact(
  value: number,
  locale: "cs" | "en"
): string;  // "1,2 M" / "1.2M" pro velké hodnoty v grafech
```

**Locale mapping**: app level `locale = "cs" | "en"` → Intl level `"cs-CZ" | "en-US"`. Žádné per-region varianty v MVP (žádné cs-SK / en-GB rozlišení).

### Currency selection

- Per uživatel preference (v user_metadata po signupu, dlu CZK).
- Per scénář override (user může mít scénář v EUR, dashboard v CZK).
- Žádný kurzový převod v MVP — currency je čistě display. (Pokud user srovnává CZK scénář s EUR scénářem, výsledky se zobrazí v cílové currency bez konverze. Dokumentováno v UI nápovědě.)

### CI parita check

`packages/i18n/scripts/check-parity.ts` jako pre-commit hook + GH Action:
1. Načte `cs.json` a `en.json`.
2. Rekurzivně porovná key paths — fail pokud `en.json` postrádá nebo má navíc klíč.
3. Volitelně lint na prázdné stringy.

### Typed keys

Generovaný `keys.ts` z `cs.json` (zod schema parse + recursive type). Volá se přes `tsx scripts/generate-keys.ts` při změně JSON. Result: `t("calc.compound.title")` je autocomplete + typo-safe.

## Důsledky

- **Plus**:
  - Jediný source of truth pro messages → žádný drift web/mobile.
  - ICU MessageFormat = škálovatelné na další jazyky bez refaktoru.
  - Typed keys = compile-time chyba při typo.
  - `Intl.NumberFormat` = zero-dep, dobře testované, RTL ready.

- **Mínus**:
  - 2 i18n knihovny (next-intl + i18next) — každá s vlastní API, devs si musí zvyknout. Mitigace: thin wrapper hook na obou stranách (`useT(namespace)`) — vrátí stejný interface.
  - `i18next-icu` má slightly different plural syntax edge cases vs next-intl. Mitigace: parity test (CI) renderne ten samý klíč na obou platformách a porovná output.
  - Hermes engine pre RN 0.74 nepodporuje `Intl.NumberFormat` plně (pre-0.73 chybí, 0.73+ partial). Mitigace: Expo SDK 53 = RN 0.76 → plně podporováno. Pokud target nižší → polyfill `@formatjs/intl-numberformat`.

- **Neutral**:
  - Date formátování řešíme stejnou cestou (`Intl.DateTimeFormat`), žádný date-fns/dayjs v MVP.

## Alternativy zvažované

- **`next-i18next` místo `next-intl`**: starší, založené na i18next — sdíleli bychom *runtime* lib s mobile. Ale `next-i18next` nepodporuje App Router prvně-class (Pages Router-first), v 2026 je `next-intl` jasný winner pro App Router.
- **`react-intl` (FormatJS) na webu i mobile**: vážná unifikace, ale ekosystém na webu pomalý k adopci App Router. Skip.
- **`i18n-js` mobile**: lighter než i18next, ale neumí ICU plurals out of the box. Skip.
- **`numeral.js` / `currency.js`**: zbytečné když `Intl.NumberFormat` dělá totéž zero-dep.
- **Crowdin / Lokalise hosting**: skvělé pro tým 5+ překladatelů, overkill pro 2-language hobby projekt. Defer.
